`required` в advertised `inputSchema` — прямая проекция zod-required, поэтому one-of ограничения (таргет `symbolId | name | file+line+col`, пары вроде `removeParam | reorder`) в схеме не выражены. Для read-опов это терпимо; для МУТИРУЮЩИХ схема в `tools/list` — последний дешёвый гейт перед вызовом с `apply:true`, и он пропускает вызовы вообще без таргета.

Проходят харнесный гейт:

- `change_signature {}` — `required` отсутствует целиком (ни таргета, ни `removeParam`/`reorder`)
- `rename_symbol {"newName":"X"}` — `required:["newName"]`, таргета нет
- `move_symbol {"dest":"…"}` / `extract_symbol {"dest":"…"}` — `required:["dest"]`, таргета нет
- `impact_type_error {"edit":{}}` — `edit` это `additionalProperties:false`, но `replace` и `remove` оба optional
- `css_cascade {}` — `file+class` XOR `selector` не выражен
- `find_usages {}` — одиночный таргет XOR `symbols[]` не выражен
- `member_usages {"member":"x"}` — `required` только `member`, тип-таргет не заявлен

Лжи здесь нет: всё ловится zod `.refine` на диспатче с внятной ошибкой. Цена — раунд-трип, и для `apply`-вызова это худшее место, чтобы её платить.

Подход: «хотя бы одно из» выразимо в JSON Schema как `anyOf` по `required` — `{"anyOf":[{"required":["symbolId"]},{"required":["name"]},{"required":["file","line"]}]}`. Автовывод из zod `.refine` в общем случае невозможен, но для мутирующих опов (их 7) ручной override оправдан: их схема — гейт перед записью.

`argsHint` в description сейчас единственное место, где one-of записан текстом. Он не дублирует схему, а подпирает её — убирать его нельзя, пока схема не выражает ограничение сама.

Готово, когда: у каждого мутирующего опа схема отвергает вызов без таргета на границе харнеса, и тест это фиксирует.

## Подтверждение из телеметрии

В `~/.codemaster/usage/fail.jsonl` этот класс реально стреляет: `member_usages {"member":"createdClinicalEntries"}` (ts=1785149326134) и `member_usages {"member":"dirtyGuard"}` (ts=1785241241797) — оба без таргета, оба прошли гейт харнеса (`required:["member"]`) и упали на zod. То есть проблема не гипотетическая: агенты именно так и вызывают, потому что схема разрешает.

## Решение

`OpDefinition.requiredOneOf` — «хотя бы одна из веток», рендерится в `anyOf:[{required:[…]},…]`.

Ключевое: ts-таргетные опы (16 штук — мутирующие И читающие) НЕ объявляют ветки вручную. Объявлен `TS_TARGET_ONE_OF = [['symbolId'],['name'],['file','line']]` в `src/ops/ts-target.ts`, и `requireTarget.predicate` СТРОИТСЯ из него. То есть advertised `anyOf` и zod-гейт не могут разойтись by construction, а не по тесту. Дифференциальный тест сверяет производный предикат со старым ручным на всей решётке из 32 входов (включая вырожденные `file` без `line`, `col` без `line`, обе ветки сразу).

Ручные ветки (`css_cascade` file+class ⊻ selector, `find_usages` +`symbols`) пиновятся двусторонним тестом: КАЖДУЮ объявленную ветку zod должен ПРИНЯТЬ (advertised-ветка, которую гейт отвергает, хуже нынешней вседозволенности — харнес пропустит, а мы откажем уже после того, как агент нам поверил), и объект, удовлетворяющий `required`, но ни одной ветке, zod должен отвергнуть.

Не покрыто одной группой: `change_signature` removeParam⊻reorder, `impact_type_error.edit` replace⊻remove (вложенный уровень), `i18n_lookup` «не более одного» → [[t-359677]]. Таргетная группа у `change_signature` при этом стоит, то есть `change_signature {}` схемой уже отвергается.

Цена диагностики (замерено): MCP SDK-клиент не валидирует аргументы по `inputSchema`, поэтому по этому пути агент по-прежнему получает наше точное §7-сообщение. Строгий харнес отобьёт вызов раньше своим generic-сообщением — человекочитаемая формулировка one-of при этом остаётся рядом, в `description` тула (`argsHint`), который для того и не убран.
