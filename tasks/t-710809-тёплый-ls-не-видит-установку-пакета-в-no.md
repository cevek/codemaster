## Проблема

Тёплый LS (`createSingleProgram`, `src/plugins/ts/program/single.ts`) не видит установку/удаление пакета в `node_modules` для импортёров, чьи файлы не менялись: при пересборке Program TS переиспользует резолв модулей неизменённых файлов (structure reuse; `hasInvalidatedResolutions` у нашего `LanguageServiceHost` нет), а версия файла в `files` меняется только через reindex. `node_modules` gitignored → §3.5-проверка его не репортит; даже правка `pnpm-lock.yaml` даёт `reindex` без инвалидации резолва. Итог: cold ≠ warm (§16 инв. 3) — тёплый демон продолжает отвечать `Cannot find module 'foo'` (и все типы через него — `any`/ошибки) после `pnpm add foo`, пока не изменится сам импортирующий файл или не перезапустится движок. Тот же вид у typecheck-гейта мутаций.

Вид ещё и history-dependent: файл, побывавший в dry-run overlay, при откате получает новый SourceFile и перерезолвится — значит один и тот же diskVersion даёт разный дисковый вид в зависимости от истории запросов.

## Repro (evidence: repro)

Скрипт: tmp-проект с `src/a.ts` = `import { x } from 'foo'`, `createTsProjectHost(dir)`, `getSemanticDiagnostics(a)` → `Cannot find module 'foo'`; создать `node_modules/foo/{package.json,index.d.ts}`; `host.setOverlay([b.ts])`, снова `getSemanticDiagnostics(a)` → ошибка всё ещё есть; `host.clearOverlay()` → всё ещё есть. Свежий хост на том же диске — ошибки нет. (Воспроизведено на 7a46ab0+, скрипт — в разборе t-786607.)

## Минимальный исход

Решённое: при reindex, в changed-set которого есть lockfile / `package.json` / `pnpm-workspace.yaml` (сигнал install), инвалидировать резолв — реализовать `hasInvalidatedResolutions`/пересоздать LS программы или бампнуть версии всех файлов программы. Открытая развилка (ниже, не для первого шага): ловить install без изменения tracked-файлов (stat маркеров `node_modules/.modules.yaml` и т.п. на входе op).
