## Задача
Два пункта одного механизма — памяти процесса MCP-фасада (`serveMcp`) о том, что уже сказано в этой сессии (одно подключение клиента).

### 1. Версия
- Отдельный идентификатор сборки (build id), НЕ константа `VERSION` из `src/bin.ts` — она ключует `socketPath` и pidfile, хэш в ней плодит демон на коммит. Сокет не трогать.
- Формат: `<версия пакета> @<sha9>` + пометка незакоммиченных правок; без git / вне собственного checkout — честное `unknown`. Git спрашивать о собственном дереве codemaster (корень пакета через `import.meta.url`) и проверить, что toplevel = корень codemaster — установленный в `node_modules` чужого git-проекта codemaster иначе выдаст HEAD юзера за свою версию.
- Сообщает тот, кто выполняет код: демон (`DaemonInfo` / проводной ответ) → мост; старый демон без поля → `unknown`, не версия моста. Вплоть до engine-child (feedback `cm=`).
- Показ: шапка `status` всегда; одна строка в первом текстовом ответе сессии (не в bare json); `serverInfo.version` тоже (знать: прокси хоста кэширует `initialize`, там может отставать).
- Свести `'0.1.0'` / `package.json 0.0.0` / литералы версий плагинов к одному источнику, если это не ломает ключ сокета.

### 2. Обучение один раз за сессию
- Сессионная память — только на фасаде (L5/format, опция `serveMcp`, по умолчанию выкл., включается в `bin.ts`). `Result`, `format:'json'`, sql, CLI, cold==warm — без изменений.
- Повторяющаяся статическая проза получает стабильный id и структуру «факт + объяснение». Первый показ в сессии — полный; дальше — компактная форма, которая ОСТАЁТСЯ утверждением: маркер `!!`, числа, имена конфигов, target этого ответа + `[id]`. Полный текст достаётся вызовом (например `status {concept:"<id>"}`) — независимо от истории сессии. Одна строка о соглашении `[id]` в `SERVER_INSTRUCTIONS`.
- Дедуп и внутри одного ответа (batch, мульти-таргет `find_usages`, sql).
- Показ засчитывается, только если текст уцелел после всех обрезок (per-op cap, `joinSectionsCapped`, `capResponse`).
- Ключ свёртки учитывает root, где проза репо-зависима.
- Стейл-баннер `PRE-EDIT` — тревога, не обучение: остаётся в КАЖДОМ ответе, после первого полного показа — короткая форма (пин ≤250 и тест «на каждом stale-ответе» сохранить, добавить проверку короткой формы).
- Повторный `status` в сессии — разница вместо полного каталога+concepts (t-109681); `full:true` / `op:` выдают полное всегда.
- Объём — ВСЕ источники повторяющейся обучающей прозы, не только топ (решение юзера). Стартовая карта (поиск, не полнота — проверь): `lowerBoundNote`, `SYNTACTIC_SCOPE` / `SYNTACTIC_NOTE` (search_symbol, symbols_overview, source-syntactic) / `surfaceModeNote`, scan-coverage заметки и `EMPTY_SCAN_DOCTRINE`, unused-exports-scope, `allProgram=` и `imports: N collapsed` в find_usages, `renderDisclosures` (`!! CANNOT CLAIM`), `capMarker`, FAIL-футер про feedback, `*_GROUPBY_NOTE` / `PROPS_TEXT_NOTE`, redirect-проза `ops/guard/navigate.ts`, `CONCEPTS_LINES` в status.

## План

### Посылки, проверенные по коду
- Вся проза рендерится в фасаде из `OpResult` (`mcp/render-response.ts` → `format/render/render-result.ts`); `Result` ходит по проводу как данные. Значит свёртку можно сделать целиком в L5/format, не трогая `Result`, json, sql-таблицы, CLI и cold==warm (§16 inv.3 — про результат op, не про текст фасада).
- Сессия = один `serveMcp` (одно подключение клиента). В режиме daemon фасад живёт в мосте — у каждого клиента своя память.
- `VERSION` в `bin.ts` ключует `socketPath` и pidfile; `StatusView.daemonVersion` и `DaemonInfo.version` (feedback `cm=`) идут из `Orchestrator.deps.version`; engine-child берёт версию из env родителя (`CODEMASTER_ENGINE_VERSION`) — т.е. сейчас врёт, если исходники сменились между стартом демона и форком.
- Инвентарь источников (помощник, поиск по `src/**` литералов ≥60 симв.): ~60 единиц в 7 каналах — `data.note`, `data.notes[]`, `data.scanned.scope`/`notAVerdict`, `disclosures[].note`, `truncated.hint`, `failure.message`, рендер-только (FAIL-футер, `capMarker`, маркер `joinSectionsCapped`). Карта таски его не покрывала: scan-coverage S1–S6, `trace-type-widening-scope`, `FLOOR_NOTE`, `COMPONENTS_NOTE`, construction/discrimination per-row `note`, navigate `gives:`, `no-symbol-hint`, `list-inactive-hint`, mutation-gate notes и др.

### Механизм (одна развилка — главная)
**Урок** = `{ id, full, short, scope: 'session'|'root' }` (`common/lesson/` — тип + `defineLesson`, чистая логика). `full` — ТОЧНАЯ статическая подстрока, которую продюсер вставляет как есть (`${LESSON.full}`); факты (числа, имена конфигов, target, `!!`-маркер) остаются в продюсере вокруг неё. Продюсеры переписываю в форму «факт + `${урок.full}`»; где объяснение зависело от слов op (subject/noun) — переформулирую нейтрально, иначе вариант = отдельный урок.

Свёртка (`format/render/fold-prose.ts`, чистая): `ProseFold = (s) => s`, применяется к КОПИИ `Result` перед condense — ко всем строкам, кроме span-подобных объектов (`file`+`text`), тел `source` и ячеек sql-таблицы, — и к собственным строкам рендера (FAIL-футер, хвост `capMarker`, маркер `joinSectionsCapped`). Каждое вхождение `full`: первое в ответе, не показанное в сессии → остаётся; иначе → `${short} [${id}]`. `short` — сжатое утверждение (например `count is a FLOOR`), не указатель. Без `fold` (CLI, json, тесты format) вывод байт-в-байт прежний.

Развилка: альтернатива — ops кладут в `Result` структурные ссылки на уроки. Отклонено: меняет `Result`/json/sql, что запрещено решением. Риск выбранного — свернуть совпавший текст в данных: закрыт денайлистом span/source/sql и длиной фрагментов (≥40 симв., тест реестра); дорогой случай — `source` по самому codemaster, его тело — span → не сворачивается.

**Реестр** (`mcp/lessons.ts`, L5 — импортирует уроки из ops/plugins/format): явный список. Тесты реестра: ids уникальны; ни один `full` не содержит другой `full` (порядок замены не важен); каждый `defineLesson` в `src/` есть в реестре (страж полноты по символу через codemaster/grep определений).

**Память сессии** (`mcp/session-memory.ts`): `Set` ключей `id#hash(full)[@root]`. Ответ: `beginResponse()` → фолдер на секцию (root секции = request.root ?? tool root ?? cwd) → рендер → `capResponse` → `commit(final)`: урок засчитан показанным, только если `full` есть в итоговом тексте (после per-op cap, `joinSectionsCapped`, seam cap). Дедуп внутри ответа (batch, мульти-таргет, sql `return:'all'`) — тем же фолдером.

**Раскрытие**: `status {concept:"<id>"}` печатает `full` из реестра независимо от истории (неизвестный id → список id). Концепты `status` (`CONCEPTS_LINES`) становятся уроками с id `targets`, `dials`, … — одно пространство имён. В `SERVER_INSTRUCTIONS` одна строка о соглашении `[id]`.

### Build id
- `support/build-id/`: `packageVersion(pkgRoot)` (читает `package.json`) и `buildId(pkgRoot)` → `0.1.0 @<sha9>[+dirty]` | `0.1.0 @unknown`. Git: `rev-parse --show-toplevel` (realpath = корень пакета, иначе unknown — защита от чужого HEAD в `node_modules`), `rev-parse HEAD`, `status --porcelain`; синхронно, с таймаутом, один раз на процесс.
- Каждый процесс считает свой: демон/in-process (`Orchestrator.deps.build`), engine-child (сам, env-версия уходит) → `DaemonInfo.version` для feedback `cm=`.
- Провод: опц. `build` на ответах `request`/`status`/`daemon-info` (старые мосты его срезают — схемы не strict; `daemonInfoSchema` получает опц. поле). Мост кэширует как `sourceStale`; отсутствие → `unknown`, НЕ версия моста. `OrchestratorApi.buildId(): string | undefined`.
- `serverInfo.version`: мост перед `serveMcp` делает один `daemon-info` пинг (ограниченный дедлайн). Прокси хоста кэширует `initialize` — пишу в доку.
- Показ: шапка `status` всегда (`codemaster 0.1.0 @abc123def+dirty pid=…`; старый демон → `… @unknown (daemon predates build ids)`); одна строка в первом текстовом ответе сессии (не bare json); `codemaster daemon status` тоже.
- Один источник версии: `package.json` → `0.1.0`; `VERSION` и литералы версий плагинов читают его (`packageVersion`). Ключ сокета остаётся `0.1.0` — значение не меняется.

### Уточнения к плану
1. **`Result` остаётся байт-в-байт прежним: извлечение, не переформулировка.** Уроком регистрирую самый длинный существующий непрерывный статический отрезок (`full` = те же слова), продюсер вставляет `${X.full}`. Тогда json, CLI, golden и тесты с regex по заметкам не меняются. Переформулировка — только где статический отрезок слишком короток, и только после grep `test/` по старой формулировке.
2. **Вложенные константы режу по существующим швам интерполяции**: `SURFACE_SCOPE_CLAUSE` — отдельный урок; остаток `SYNTACTIC_SCOPE`, `SYNTACTIC_NOTE`×2, `SYNTACTIC_SOURCE_NOTE` — свои уроки. Конкатенация даёт те же байты, инвариант «ни один `full` не содержит другой» выполним.
3. **Build id считается жадно при старте процесса** (демон, in-process, engine-child — каждый при своём старте), не лениво: ленивый memo показал бы HEAD диска при коде, загруженном раньше.
4. **Денайлист узкий**: не сворачиваю только поле `text` span-подобных объектов, `decl.text`, тела `source` и ячейки sql-таблиц — `note` рядом со span в той же строке сворачивается. Секции batch с `format:'json'` не сворачиваются никогда (явный обход в пути batch).
5. Порядок обхода копии `Result` = порядок рендера (failure → data → disclosures → truncation hint): полный текст — первое, что встречает читатель.
6. Строка сборки не защёлкивается на `unknown`: при смене `unknown → известный` строка выдаётся снова.
7. Старый демон + новый мост: незнакомая формулировка проходит без свёртки, `[id]` раскрывается из того же реестра — отдельный тест.
8. `package-lock.json` (корневой `version`) — в том же коммите, что `package.json` 0.0.0 → 0.1.0.
