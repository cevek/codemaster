## Задача
Два пункта одного механизма — памяти процесса MCP-фасада (`serveMcp`) о том, что уже сказано в этой сессии (одно подключение клиента).

### 1. Версия
- Отдельный идентификатор сборки (build id), НЕ константа `VERSION` из `src/bin.ts` — она ключует `socketPath` и pidfile, хэш в ней плодит демон на коммит. Сокет не трогать.
- Формат: `<версия пакета> @<sha9>` + пометка незакоммиченных правок; без git / вне собственного checkout — честное `unknown`. Git спрашивать о собственном дереве codemaster (корень пакета через `import.meta.url`) и проверить, что toplevel = корень codemaster — установленный в `node_modules` чужого git-проекта codemaster иначе выдаст HEAD юзера за свою версию.
- Сообщает тот, кто выполняет код: демон (`DaemonInfo` / проводной ответ) → мост; старый демон без поля → `unknown`, не версия моста. Вплоть до engine-child (feedback `cm=`).
- Показ: шапка `status` всегда; одна строка в первом текстовом ответе сессии (не в bare json); `serverInfo.version` тоже (знать: прокси хоста кэширует `initialize`, там может отставать).
- Свести `'0.1.0'` / `package.json 0.0.0` / литералы версий плагинов к одному источнику, если это не ломает ключ сокета.

### 2. Обучение один раз за сессию
- Сессионная память — только на фасаде (L5/format, опция `serveMcp`, по умолчанию выкл., включается в `bin.ts`). `Result`, `format:'json'`, sql, CLI, cold==warm — без изменений.
- Повторяющаяся статическая проза получает стабильный id и структуру «факт + объяснение». Первый показ в сессии — полный; дальше — компактная форма, которая ОСТАЁТСЯ утверждением: маркер `!!`, числа, имена конфигов, target этого ответа + `[id]`. Полный текст достаётся вызовом (например `status {concept:"<id>"}`) — независимо от истории сессии. Одна строка о соглашении `[id]` в `SERVER_INSTRUCTIONS`.
- Дедуп и внутри одного ответа (batch, мульти-таргет `find_usages`, sql).
- Показ засчитывается, только если текст уцелел после всех обрезок (per-op cap, `joinSectionsCapped`, `capResponse`).
- Ключ свёртки учитывает root, где проза репо-зависима.
- Стейл-баннер `PRE-EDIT` — тревога, не обучение: остаётся в КАЖДОМ ответе, после первого полного показа — короткая форма (пин ≤250 и тест «на каждом stale-ответе» сохранить, добавить проверку короткой формы).
- Повторный `status` в сессии — разница вместо полного каталога+concepts (t-109681); `full:true` / `op:` выдают полное всегда.
- Объём — ВСЕ источники повторяющейся обучающей прозы, не только топ (решение юзера). Стартовая карта (поиск, не полнота — проверь): `lowerBoundNote`, `SYNTACTIC_SCOPE` / `SYNTACTIC_NOTE` (search_symbol, symbols_overview, source-syntactic) / `surfaceModeNote`, scan-coverage заметки и `EMPTY_SCAN_DOCTRINE`, unused-exports-scope, `allProgram=` и `imports: N collapsed` в find_usages, `renderDisclosures` (`!! CANNOT CLAIM`), `capMarker`, FAIL-футер про feedback, `*_GROUPBY_NOTE` / `PROPS_TEXT_NOTE`, redirect-проза `ops/guard/navigate.ts`, `CONCEPTS_LINES` в status.
- Прежний запрет (комментарий в `src/ops/lower-bound-note.ts`, тело t-584829, соответствующее место ARCHITECTURE §12/§16) переписать под новое решение в present-state.
