`captureWorktree` (`support/git/worktree-snapshot.ts`) с фильтром `affectsTypecheck` (`plugins/ts/gate-membership.ts`) хэширует ВСЕ грязные .ts/.json репо; `preWriteCheck` (`ops/post-apply-verify.ts`) отказывает при любом расхождении. Автосейв редактора, соседний агент в том же дереве или `package-lock.json` во время `npm i` дают «re-run» даже когда файл не входит ни в одну программу гейта.

Решённый минимум: пересечь список дрейфа с файлами программ `gateAcross().programs` (`containsFile` на входной версии) ∪ структурные пути (`tsconfig*`/`package.json`/`pnpm-workspace.yaml`/`.gitignore`) ∪ touched. Нужен оракул: e2e — правка файла вне всех `include` во время гейта не отказывает, правка файла программы отказывает.


## План

Трек: t-500739 (забор дрейфа шире scope гейта) + t-835778 (пути `gitStatus` при root = подкаталог git-репо).

### t-835778 — воспроизведено
Repro (временный репо, `tsconfig` в `sub/`, `sub/src/a.ts` грязный): `rename_symbol {name:foo,file:src/a.ts,newName:baz} --root $T/sub --apply` → `applied=true`, грязный `a.ts` переписан без `dirtyOk`. Контроль: тот же репо с `--root $T` и `file:sub/src/a.ts` → `touched files have uncommitted changes`. Subdir-root — штатный путь: §5-L2 сам рекомендует `root:<pkg>` для rename с якорем вне primary.

Проверенные факты git (из `sub/`): `git status --porcelain` всегда toplevel-relative (`sub/src/a.ts`, `shared/x.ts`), флага `--relative` нет; `git rev-parse --show-prefix` → `sub/` (в toplevel — пустая строка); `git diff --name-only --relative` → cwd-relative и отбрасывает пути вне cwd; `git ls-files` уже cwd-relative (`ls-source-files.ts`, `ls-ignored-sync.ts` в subdir верны).

Скоуп:
- `support/git/status.ts` `gitStatus`: параллельно со status — `rev-parse --show-prefix`; пути ребейзятся на workspace root: внутри root → `dirtyPaths` (root-relative — контракт, который читают все потребители), вне root → новое поле `outsideRoot` (root-relative `../…`). `porcelain` не меняется → fingerprint остаётся repo-global (дрейф вне root по-прежнему двигает его). Ребейз — чистая функция в `support/git/` (тестируется отдельно).
- `support/git/diff-changed.ts` `gitDiffNames`: `--relative` (freshness `changed` — тот же класс).
- `support/git/diff-against.ts` `gitDiffAgainst`: без `--relative`, тем же ребейзом → `{inside, outside}` (affected обязан сказать о выкинутом).
- Потребители `gitStatus`/`gitRepoFingerprint`/diff:
  - `daemon/freshness.ts`: `statDirty`/`changed` получают корректные root-relative ключи (сейчас в subdir-режиме реиндекс получает несуществующие `sub/…` пути — грязная правка не доходит до плагинов). `cleanAtCommit` = `dirtyPaths ∪ outsideRoot` пусто — анкор остаётся repo-global (иначе грязный файл вне root дал бы «clean at HEAD» — новая ложь). Пути `../…` в `reindex` НЕ передаются: `RepoRelPath` по контракту `mintRepoRelPath` не выходит за root, а ts-хост ключует внешние файлы абсолютным путём — дыра «freshness не реиндексит файлы программ вне root» существовала и до правки → таска.
  - `ops/affected.ts`: in-root пути теперь совпадают с ключами программы; вне root — дисклоз в `mode` («N changed path(s) outside the workspace root — not traced»), не молчаливое выпадение (сейчас такие пути ложно классифицируются `deleted`).
  - `support/git/worktree-snapshot.ts` `captureWorktree`: хэширует `dirtyPaths ∪ outsideRoot` (`path.join(root, '../x')` корректен); dirty-гейт `touched ∩ dirty` — по in-root набору.
- Тот же класс вне `gitStatus`: `plugins/ts/syntactic-cache.ts` `computeSurfaceKey` сам парсит porcelain и хэширует `root/<toplevel-path>` → в subdir-режиме ключ не двигается от правки грязного файла → таска (потребителей класса: 6 — freshness, affected, diff-against, fingerprint, worktree-snapshot исправлены; syntactic-cache — таска).

### t-500739
- `plugins/ts/gate-membership.ts`: `gateRelevance(ctx, restrictTo)` → предикат `(rel) ⇒ restructures(rel) ∨ ∃ program ∈ restrictTo: containsFile(absOf(rel)) ∨ mayContain(absOf(rel))`. `absOf` резолвит и `../x`.
- `TsPluginApi.gateRelevance(restrictTo)` — аддитивно в `api.ts`/`plugin.ts`.
- `ops/post-apply-verify.ts` `preWriteCheck`: новый параметр-предикат; дрейф = `HEAD` ∪ пути, где `relevant(rel) ∨ rel ∈ touched`. Вызыватели (`refactor-apply.ts`, `refactor-plan-apply.ts`) передают `ts.gateRelevance(gateProgms)`.
- `captureWorktree` сохраняет префильтр `affectsTypecheck` (ограничивает хэширование).

Развилки:
1. Фильтр на проверке, не на захвате: на `captureEntry` программы ещё не выбраны (захват до гейта — обязателен, гейт синхронный).
2. `containsFile ∪ mayContain` (как приватный `owns` в program-gate.ts), а не только `containsFile` из постановки: новый файл под глобом программы во время op меняет программу (глобальная декларация) — `containsFile` его не видит. `owns` не экспортирован, program-gate.ts — файл соседнего трека, поэтому два вызова повторены в gate-membership.
3. Набор программ = `gateAcross().programs` (проверенные); degraded-сиблинги в вердикт не вошли.
4. `--show-prefix` — без кэша, в `Promise.all` со status: латентность не растёт, кэш per root — новый механизм инвалидации ради ~3 мс.

Проверка поведения:
- unit, реальный git, root = подкаталог: `gitStatus` → root-relative + `outsideRoot`; `gitDiffNames`/`gitDiffAgainst` ребейз.
- unit `preWriteCheck`, root = подкаталог: грязный touched отказывает (симптом репро; красный до фикса).
- e2e `post-apply-verify`: правка файла вне всех `include` во время `gateAcross` → применяется (красный до фикса); существующий тест на `src/other.ts` остаётся отказом; новый файл под глобом `include` во время гейта → отказ (пиннит развилку 2).
- freshness (§3.5) в subdir-режиме: `project()` получает аддитивную опцию git-корня выше workspace; правка файла → следующий запрос видит её без вотчера (красный до фикса, если LS-хост сам не перечитывает).
- живой: `/tmp/t835778-repro.sh` → `dry-run`, `uncommitted changes`.

Ревью: plan-reviewer (1 круг), bug-reviewer на код (до 2 кругов).
