Repro (/tmp-фикстура, воспроизводится заново): tsconfig {strict, module:commonjs, allowJs, checkJs, esModuleInterop, types:[]}, src/req.d.ts `declare function require(s: string): any;`, src/model.ts экспортирует setName, src/types.ts `export const other = 1;`, src/ui/use.js:
```
const types = 2;
const M = require('../model');
exports.r = (m) => M.setName(m, 'x' + types);
```
`move_symbol {name:setName, file:src/model.ts, dest:src/types.ts}` (dry-run) → `typecheck=clean` (preExisting не показан вовсе), diff в use.js: `const M = require('../model'), types=require("../types");` и `types_1.setName(...)`. `tsc --noEmit -p .` на том же post-состоянии: TS2440 Import declaration conflicts with local declaration of 'types' + TS2552 Cannot find name 'types_1' (+ pre-existing TS7006). Т.е. typecheck-гейт (§7, `program-gate`/`diagnostics`) не учитывает диагностику JS-файлов программы — 'clean' на сломанном дереве, ложь §3. Сама порча имени чинится в t-698933 (нормализатор namespace-импорта), но гейт как бэкстоп слеп для .js. Не исследовано: отфильтрованы ли .js-файлы явно или checkJs-диагностики не запрашиваются.



## Решение по объёму
Полная проверка .js в гейте не делается (JS в проектах-целях не пишут). Минимальный исход — только честность: при allowJs+checkJs ответ мутации несёт строку, что .js-файлы проектом проверяются, а гейтом нет. Брать попутно, когда трек и так в коде гейта.
