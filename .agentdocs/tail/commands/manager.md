## Специфика codemaster

**Мерило required-vs-backlog — инварианты проекта** (ARCHITECTURE §1/§3): never-lie (proof-carrying,
явная неопределённость `unresolved/partial/dynamic`, no silent-truncation), never-hang (дедлайн, no
unbounded loop, no per-call repo-scale работа), строгий лейеринг (downward-only, plugin-DAG,
`common/`→`core/`), файл ≤300 строк, внешние вызовы обёрнуты → `ToolFailure`, boundary-вход
zod-валидирован.

**Добор порождённых задач (§9) в этом репо:** критерий (3) «приоритет оправдывает круг» читается как
`high`+ ЛИБО живая ложь в базовой ветке, про которую мы теперь ЗНАЕМ — never-lie перевешивает размер
правки.

**Механический гейт:** `npm run fix-and-check` (EXIT 0) — он же авто-сносит механический dead-code
(не правь руками). На слитом состоянии фичеветки после каждого мерджа гоняешь `npm run check` +
`npm test`. Точечно — `node --test test/foo.test.ts` (файл, не директорию).

**Параллельный тест-лок (борьба за CPU между воркерами).** Много worktree на одной машине → два
одновременных полных `npm test` (>1 мин, все ядра) не займут 2×, а трэшат суперлинейно (грызня за
каждое ядро). Machine-wide **мьютекс K=1** сериализует тяжёлые прогоны: helper
`~/.codemaster-orch/with-test-lock.mjs` (атомарный `open('wx')` + steal мёртвого/протухшего холдера +
release на exit/сигналах), вызов `node ~/.codemaster-orch/with-test-lock.mjs -- npm test`. Ты
(менеджер) **провижнишь helper при старте если его нет** (атомарный лок-скрипт на fs), и на КАЖДОМ
мердж-гейте гоняешь полный сьют/`fix-and-check` через ТОТ ЖЕ лок — одна очередь с воркерами, менеджер и
воркеры не сталкиваются. Лок ещё и выставляет `TEST_CONCURRENCY=ядра−4` (замер: ≈та же wall-time что на
max, но машина не забита под ноль + меньше contention-флака; хвост сьюта wait-bound e2e, не CPU); npm
test-скрипты читают эту env, CI (без лока) гонит на default-max. Замер concurrency — эксперименты выше.
В бриф воркеру: таргетные `node --test <файл>` во время итерации БЕЗ лока (дёшево); полный `npm test` +
`fix-and-check` на DONE ЧЕРЕЗ лок. (K=1, не семафор: полный сьют и так сатурирует все ядра, даже 2
параллельных трэшат.)

**Тест-группы** (сплит по стоимости — для локализации, не повод пропускать прогон): `test:light`
(unit+golden, ~12с — inner-loop) · `test:heavy` (e2e+differential — real-spawn + cold-Program-оракулы,
~90% времени сьюта) · `npm test` = всё, авторитет для мердж-гейта. Профиль — `npm run test:timing` →
test-timing.html.

**Source-of-truth доки:** CLAUDE.md · ARCHITECTURE.md (§1 north star, §3 trust) · CONTRIBUTING.md ·
src/README.md (лейеринг). Backlog — **task-manager** (MCP): сначала его `help` + `explain_config`,
правь через MCP, не руками.

**Догфуд:** codemaster MCP жив на этом репо — символьные / типовые / usage-вопросы (и свои, и в
брифах) веди через него, не grep. Собери `feedback` воркеров ДО их архивации — окно одно.

**Инбокс догфуда — твой, и он НЕ второй backlog.** `~/.codemaster/feedback/inbox.md` копится сам;
непротриаженный, он становится конкурирующим списком открытой работы (половина находок живёт только
там) — тот же класс лжи про объём, что два таска на один баг. Инвариант: **инбокс непустой ⇒ есть
непротриаженное**. Читай сам ФАЙЛ, не пересказ воркера (пересказ — тот же релей-вместо-источника, за
который ты гоняешь их), после каждого DONE: конвертнул → перенёс в `archive/` с маппингом
`запись → t-id`; не породило таск → тоже в архив, с причиной.

**Сливай ПО ЗАПИСЯМ, и сверяй счёт механически.** Инбокс ГЛОБАЛЬНЫЙ: туда пишут и внешние агенты из
других репо, поэтому между твоим прошлым сливом и этим там появились записи, о которых тебе никто не
докладывал. Самый частый сбой — слить «по ожиданию»: переносишь то, что воркер ОТЧИТАЛ, а в файле лежит
ещё и чужое. Поэтому: перед сливом `grep -c '^## '`, после — число строк маппинга ОБЯЗАНО сойтись с
числом записей в батче. Не сошлось — ты либо потерял находку, либо написал строку на запись, которой
там нет; архив тогда врёт в обе стороны и выглядит обработанным. Глазами эта сверка не работает —
проверено на себе дважды.

**Внешние находки весят больше, а приходят реже.** Внешний агент (работает в чужом репо, инструмент
только использует) не может перезапустить демон, не может править конфиг в своём репо без побочек и не
видит исходников — его находки про НЕПРИГОДНОСТЬ, а не про неудобство. Внутренние (правят сам
инструмент) докладывают чаще и владеют словарём. Приоритизация по объёму фидбэка систематически
пере-обслуживает внутренних — взвешивай, а не считай.

**Естественные швы декомпозиции:** плагины (`plugins/ts|scss|i18n|schema|react|react-query|…`)
edit-disjoint по домену; `ops/` компонуют плагины поверх (сидят над DAG). Shared-seam (напр.
`ops/intake/resolve-target`) → отдельный трек, ОДИН владелец; зависимые вливают его в себя, когда он сел.

**Генерируемые файлы регенерируй, не сливай руками:** golden-снапшоты — проектным механизмом
(`UPDATE_GOLDEN`), не 3-way. Env-нюансы: fish не ест inline `VAR=cmd` → `env VAR=… cmd`;
`node --test <файл>`, не директорию.

**Реальные грабли-классы этого репо:**

- Гипотеза о root-cause часто НЕВЕРНА → отдавай воркеру как «воспроизведи в песочнице», не мандат.
- Рекуррентный класс бага (density-взрыв на `verbosity:full`) = неверный opt-in дефолт → чини
  инверсией на deny-by-default + компайл-страж (`Record<Tag,mode>`: новый тег без классификации =
  tsc-error), не whack-a-mole.
- Вывод выглядит сломанным → воспроизведи CLI one-shot свежим процессом ПРЕЖДЕ чем считать регрессом
  (частый стейл-демон, а не баг кода).

## Классы этого репо (универсальные — в базовом шаблоне выше)

Базовый шаблон уже несёт: цена своей протокольной ошибки, диапазон vs свои коммиты, переписываемый SHA,
инструкция-оркестратору-глушит-воркера + обязательный блок «ревью» в DONE, план-опровергающий-постановку
и таблица-по-аналогии, величины одной природы, измерь-класс-до-реформы, страж-ловит-дорогой-случай, три
категории добора. Здесь — только codemaster-специфика.

**Отказ сильнее ноты, но ЗАВЕРШЁННЫЙ пустой обход — вердикт.** Если непригодное состояние можно сделать
недостижимым (упасть выше по течению) — это лучше ноты: нота объясняет негодный ответ, отказ его не
выдаёт. Обратное так же обязательно: обход, дошедший до конца и не нашедший ничего, УСТАНОВИЛ отсутствие,
и отказ там был бы ложью наизнанку. Дискриминатор всегда «дошли ли до конца», а не «равен ли счётчик нулю»
— эту инверсию под ревью ловили дважды за волну, оба раза внутри модулей, написанных против неё же.

**Общий словарь неполноты: дели ПРОЗУ, структуру — только при совпадении единицы измерения.** Три трека
подряд отказались переиспользовать `ScanCoverage`, каждый по своей верной причине (файлы / экспорты /
ссылки), и каждый доложил вместо того, чтобы гнуть форму. Маркер и доктрину выносим в один дом
(`ops/scan-coverage.ts`), структуру — нет: её дискриминатор `walkedFiles === 0` в чужой единице выносит
вердикт, которого механизм не устанавливал. Решение о консолидации — t-381761, и правильный ответ там
скорее «извлечь инвариант», чем «параметризовать тип».
