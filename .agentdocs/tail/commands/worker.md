## Специфика codemaster

**Гейт:** `npm run fix-and-check` (EXIT 0) — авто-сносит механический dead-code (unused imports через
eslint, truly-dead exports через knip; не удаляй руками). Полный `npm test` — один раз в конце
(`npm test >/tmp/t.txt 2>&1`, грепай ФАЙЛ, не перезапускай ради разных грепов).

**Тест-группы** по стоимости: `test:light` (unit+golden, ~12с — inner-loop); `test:heavy`
(e2e+differential — real-spawn плюс cold-Program-оракулы, ~90% времени); `test:e2e` / `test:differential`
точечно; `npm test` = всё (авторитетно, на DONE). Профиль времени — `npm run test:timing` →
test-timing.html.

**Твой DONE-прогон — не последняя проверка, но первая.** Менеджер перепрогоняет гейт САМ на слитом
состоянии фичеветки после каждого мерджа — твой прогон ловит дефект раньше и дешевле того. Не
халтурь — прогони реально, на финальном коммите, зелёным; false-green всплывёт позже и дороже.

**Тест-лок (несколько воркеров на одной машине).** Два одновременных полных сьюта трэшат CPU
суперлинейно. Любой ТЯЖЁЛЫЙ прогон — полный `npm test` ИЛИ `fix-and-check` — ТОЛЬКО через machine-wide
**мьютекс K=1**: `node ~/.codemaster-orch/with-test-lock.mjs -- npm test` (и `... -- npm run
fix-and-check`). Другой держит лок → ждёшь в очереди (норма, не гоняй голый сьют). Таргетные
`node --test` — без лока. (Лок провижнит менеджер; нет helper'а — пингани, не гоняй параллельно.)

**Oracle-backed тест (§16):** независимый оракул — cold `ts.Program` / cold reparse / отдельный
код-путь; НЕ grep и НЕ golden-only; реально падает ДО фикса.

**Соответствие проекту:** главный инвариант (never-lie / never-hang, ARCHITECTURE §1/§3), лейеринг
(downward-only, `common/`→`core/`, plugin-DAG), файл ≤300 строк, внешние вызовы обёрнуты →
`ToolFailure`, boundary zod-валидирован. Source-of-truth: CLAUDE.md · ARCHITECTURE.md · CONTRIBUTING.md
· src/README.md.

**Ревьюверы ПОСТ-кода под тип правки** (поднимаешь как субагентов; план-ревью — отдельный обязательный
шаг ДО кода, см. промпт, этот список его не заменяет): `bug-reviewer` — всегда; `architecture-reviewer`
— новый seam / кросс-модуль / структура; `copy-paste-reviewer` — заметный новый код.

**Risk-остриё codemaster для брифа ревьюверу:** stale/freshness (§3.5), proof-span off-by-one
(1-based Loc ↔ 0-based offset), мисидентификация (алиас-импорт / same-name символ), silent-truncation,
необёрнутый внешний вызов, блокировка оркестратора синхронной тяжёлой работой (§2).

**Догфуд:** символьные вопросы веди через codemaster MCP; его баг/трение подай в его `feedback` сам.

## Классы, оплаченные прошлыми волнами

(Универсальное — «тест обязан уметь провалиться», ревью при запрете на субагентов, проверки синхронизации
с фичеветкой, перечень потребителей шва — живёт в базовом шаблоне выше. Здесь только то, что специфично
для этого репо.)

**Не сходится с постановкой менеджера — ДОЛОЖИ, не выравнивай молча.** Его карта собрана поиском и
аналогией: таблица потребителей API, «механизм такой-то», «хелпер уже готов» — ГИПОТЕЗЫ, и в этом репо
они опровергались регулярно. Замеренные случаи: перепись потребителей, где колонка «итерирует файлы»
заполнена по аналогии (реально оп итерировал ССЫЛКИ — выравнивание притащило бы O(программы × файлы ×
узлы) на каждый хоп); «хелпер готов, тебе подключение» при несовпадении единицы измерения; постановка
шире факта («падает везде» вместо «падает в git-репо без TS»). Расхождение — самый ценный результат
план-гейта.

**Общий словарь неполноты: бери ПРОЗУ, структуру — только при совпадении единицы измерения.**
Формулировку и маркер переиспользуй из общего дома (`ops/scan-coverage.ts` — `NOT_A_VERDICT_MARKER`,
`EMPTY_SCAN_DOCTRINE`); одна фраза в N домах = отдельный заведённый дефект. Структуру (`ScanCoverage`)
— нет, если её дискриминатор считает не в твоих единицах: `walkedFiles === 0` в reference- или
export-денominated обходе вынесет `!! NOT A VERDICT` над установленным ответом. Три трека подряд
отказались её гнуть, каждый по своей верной причине — не гни молча, доложи, что не подошло.

**Отказ сильнее ноты (§3 в частном виде).** Можешь сделать непригодное состояние НЕДОСТИЖИМЫМ (упасть
выше по течению) — так и делай: нота объясняет негодный ответ, отказ его не выдаёт. Обратное — тоже
правило: ЗАВЕРШИВШИЙСЯ обход без результата это ВЕРДИКТ, и отказ там был бы ложью наизнанку. Пустой
СКАН и пустой РЕЗУЛЬТАТ — разные факты; дискриминатор «дошли ли до конца», а не «равен ли счётчик нулю».

**Провалившееся УСТАНОВЛЕНИЕ возвращается отказом, а не `ok`, имеющим форму доказанного отсутствия.**
Резолв не нашёл цель, программа не собралась, тип не резолвится — это `fail(ToolFailure)`, не
`ok{found:0}`. И у сообщения о неполноте один рычаг на одну причину: назвать `pathInclude` там, где
программа держит 0 файлов, — инертный рычаг внутри сообщения про рычаги (t-259465).
